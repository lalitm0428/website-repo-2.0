What It Does

From a topic to a cited draft, transparently.

01

Autonomous Research Loop

The agent drives its own tool-calling loop — generating search queries, scraping pages via Firecrawl, and saving structured notes — without manual prompting. Every step streams to the browser in real time.

02

Human-in-the-Loop Essay

Before a single sentence is written the agent surfaces a structured outline for review. Nothing advances until you approve — keeping you in control of the final argument and cited draft.

03

Quiz & Summarizer

Paste any notes or reading and get auto-generated MCQ or short-answer practice questions, or a structured TL;DR summary with key points, main themes, and important terms.

04

Planner & RAG Syllabus

An AI-powered task board and weekly schedule help you plan your studies. Drop in your syllabus and the agent extracts every deadline — then uses vector similarity search to surface relevant material at write time.

How It Works

Three-phase agentic pipeline.

Phase 1

Research

  • Generate 4 search queries (LLM)
  • Parallel Tavily web search
  • Deduplicate & rank URLs
  • Parallel Firecrawl scrape
  • Snippet fallback if empty

The LLM drives the loop autonomously via tool calling. A semaphore caps concurrent scrapes at 3 to stay within Firecrawl rate limits.

→

Phase 2

Outline

  • Batch note extraction (LLM)
  • Generate structured outline
  • Stream outline via SSE
  • Await user approval

The outline is held in a server-side session store. The draft endpoint is unreachable until the client explicitly approves, enforcing the human-in-the-loop gate.

→

Phase 3

Draft

  • Approved outline + all notes
  • Streaming LLM write (SSE)
  • Inline [Source: url] citations
  • Persist session to Supabase

The essay streams token-by-token so the browser renders each sentence as it arrives. On completion the full session — notes, outline, draft — is saved to Supabase PostgreSQL.

The Impact of Artificial Intelligence on Higher Education

The rapid proliferation of large language models has triggered a fundamental reassessment of how universities deliver and assess learning. Institutions ranging from MIT to community colleges are piloting AI tutoring systems that provide on-demand, personalized feedback on student writing [Source: https://news.mit.edu/2024/ai-tutoring-pilot], while simultaneously grappling with questions of academic integrity that existing honor codes were never designed to address.

A 2024 survey of 1,200 undergraduates found that 68% had used a generative AI tool for coursework at least once, yet fewer than a third disclosed that use to an instructor [Source: https://www.pewresearch.org/2024/ai-students]. This gap between adoption and transparency reflects a broader tension: AI tools lower the floor for producing polished prose, but they do not automatically raise the ceiling for genuine comprehension or critical thought.

Leading researchers argue that the most durable educational response is not prohibition but redesign — moving toward oral defenses, process portfolios, and in-class synthesis tasks where reasoning is made visible [Source: https://educause.edu/perspectives/2025/ai-assessment]. The students who thrive will be those who treat AI as a research accelerant rather than a ghostwriter.

How It Works

Chat, plan, schedule.

Phase 1

Planner Agent

  • Message + history sent to LLM
  • Agent selects tool to call
  • get / add / update / delete tasks
  • Tool result returned to LLM

The LLM is given 5 tools and autonomously chains calls — e.g. get_tasks then add_task — within a single conversation turn.

→

Phase 2

Task Sync

  • Tool calls hit Supabase directly
  • Task board refreshes via refreshKey
  • Calendar synced with task state
  • Syllabus parsed → bulk task insert

React's refreshKey pattern causes the task board and calendar to re-fetch automatically every time the planner agent modifies data.

→

Phase 3

Schedule

  • All open tasks fetched
  • Today's date injected into prompt
  • Mon–Sun plan streamed via SSE
  • Sorted by due date & priority

The schedule prompt includes today's date so the LLM calculates days remaining and allocates study time proportionally to urgency.

How It Works

Notes in. Questions out.

Phase 1

Prompt Build

  • Notes truncated to 5 000 chars
  • Question count & format injected
  • Student profile context appended
  • JSON schema included in prompt

Pre-loaded subject cards ship with curated notes. Custom text is accepted as-is — the LLM handles any subject or language.

→

Phase 2

Generate

  • Single LLM call (no streaming)
  • JSON array parsed from response
  • Markdown fences stripped
  • Fallback: first '[' to last ']'

The backend strips code fences and parses raw JSON so the frontend receives a clean array regardless of LLM formatting quirks.

→

Phase 3

Quiz Loop

  • Question-by-question state machine
  • Answer submitted → revealed
  • Running score badge updated
  • Final screen: ring + tier message

The quiz is fully client-side after generation — no further API calls. Score and state are managed entirely in React state.
